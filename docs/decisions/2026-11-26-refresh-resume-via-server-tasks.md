# 2026-11-26 刷新页面不中断生成：生成改为服务端任务

## 背景

生成原先绑在 HTTP 连接上：浏览器一刷新，连接断，服务端在 `finally` 里取消上游，写到一半的回答就废了。
手机切后台、误触刷新、页面崩溃都会触发。用户要的是"刷新页面不中断"——生成不该因为看的人换了个连接就作废。

## 范围与非目标

- 范围只到"刷新页面不中断，任务存内存即可"。进程重启后任务丢失、用户看到半截回答收成"已停止"，这是接受的行为。
- 不做多端共享同一任务，不做任务持久化到磁盘，不做断点续传到另一个设备。
- 不改生成协议（仍是 Anthropic Messages SSE），不改消息结构。
- 不改 `docs/architecture.md`。任务（task）是实现概念，不作为业务术语登记。

## 考虑过的备选

- **保持代理直通，前端做断线重试**：刷新后请求已作废，重试等于重新生成，前面的 token 全白花，且答案会变，否决。
- **任务落盘（IndexedDB / 服务端文件）**：能扛进程重启，但要处理过期、并发写、清理，本次范围外，否决。
- **服务端内存任务 + 连接只订阅（采纳）**：把生成从连接里摘出来，任务在服务端独立跑；连接断了只是没人订阅，
  上游照跑；刷新后凭任务 id 重新订阅、从头回放。改动集中在服务端新增一层任务仓储，生成逻辑不变。

## 最终方案与理由

服务端新增内存任务仓储。任务 id **取回复消息 id**——它已随会话落盘，刷新后的客户端不需要任何额外本地状态
就能凭它查自己的在飞生成。任务记录起始块数 `baseBlocks`，因为回放是从起点整段重放的：本地已存了半截块，
直接叠加会重复，所以先裁回任务起点再重放（续写场景尤其明显）。

停止生成必须连服务端任务一起取消。只断本地订阅的话，上游会继续烧额度跑完，而且刷新回来还会被当成"仍在生成"
接回去——用户明明停过了。任务被主动停止记 `aborted` 而不记 `error`：停止不是失败，记了会让展示层对用户
自己的操作冒错误提示。

会话加载时不再无条件把未完成回复收成"已停止"：逐条问服务端该任务还在不在，在就接上继续收，只有服务端
确实没有（进程重启或过期）才停。接续时回放会补回 `message_delta` 里的标题——那帧恰在回复末尾，
刷新最容易丢的就是它，不补的话会话永远停在"新对话"。

任务 id 走查询参数而不是 URL 路径：追问 lane 的键含 NUL 分隔符，不是合法路径段。

## 遗留问题

- 刷新后 `activeId` 不持久化，落在欢迎页，要手动点进会话才看到接续；生成本身不会中断。
- 任务只在内存，进程重启或超过 TTL（30 分钟）即失效，届时半截回答收成"已停止"。
- 服务端版本号（`serverVersion`）不随本批自动前进：本次走远程自更新循环，不经过 `release.sh` 的序号自增。
