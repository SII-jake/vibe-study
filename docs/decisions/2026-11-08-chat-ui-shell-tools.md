# 2026-11-08 对话界面改版与 bash/python 工具集成

## 背景

用户提出三个痛点：网页版按回车不能发送消息（必须 Ctrl/⌘+Enter）；对话界面
（网页与手机端）不像正常聊天——用户消息与助手回答视觉混连成段，首个提问
还是大标题形态；模型没有执行工具，问当前时间只能凭记忆答。附 DeepSeek
聊天页作为形态参考。

## 范围与非目标

- 动：聊天渲染（NodePage/StartPage/AskPane/AskSheet 的输入与气泡）、服务端
  工具链（agent/tool 声明与执行）、e2e 回归脚本。
- 不动：分支树数据模型与 store、node-sync 同步协议、安卓壳、部署拓扑；
  轨道多栏布局保持原样，只换消息与输入区的视觉形态。
- 不做：沙箱隔离的代码执行、markdown 渲染管线升级、多模态输入；工具的
  对外暴露策略保持现状（仍受登录门卫与内网自用前提约束）。

## 考虑过的备选

- 气泡只改追问不动首条提问：否决——参考形态下所有用户消息同构，首轮
  提问用大标题会把「对话」退化成「文档」，与改版目标相反。
- Shift+Enter 发送、Enter 换行：否决——用户明确要求「回车就发送」，
  且手机端没有 Shift 概念，Enter=发送才是跨端一致的默认。
- bash/python 合为一个 run_shell(command, runtime)：否决——拆两个声明后，
  工具描述可分别写清「取系统状态」与「验证代码行为」两类动机，模型选型更稳。
- 工具复用搜索密钥的存在作为 agent 启用条件：否决——shell 工具不依赖
  搜索密钥；另设独立开关 SHELL_TOOLS，启用条件改为「搜索密钥或开关任一」。
- 子进程去 shell 化（execFile + 参数数组）：未采纳——模型生成的本来就是
  一段 shell 文本（管道、重定向、复合命令），去 shell 化语义对不上；以单
  进程 + detached 进程组 + 组杀守住超时与孤儿进程两条底线即可。
- 在 vitest 里跑工具的 child_process 测试：否决——vitest 环境缺
  TextEncoderStream，流式 stdout 采集直接失败；独立成 node --test
  子进程测试先跑，vitest 只收纯单元用例。

## 最终方案与理由

- 用户消息统一右侧色块气泡（提问/追问同形态），助手回答平铺；输入区
  收拢为圆角芯片，Enter 发送、Shift+Enter 换行、IME isComposing 拦截
  （中文输入法下不误发）。
- 新增 run_bash / run_python：stdout/stderr/退出码/超时如实回传、输出
  截断、进程组超时组杀；SHELL_TOOLS 开关默认关，启用后接入既有 agent
  工具循环并把工具动作以状态行推给前端。
- 工具指南显式写清「取系统当下状态 / 验证代码真实行为」两类动机，与
  search 的「时效与事实核查」分开，避免混用。

## 遗留问题

- 工具在服务器本机执行，无沙箱/权限边界：当前接受，前提是登录门卫 +
  内网自用形态；若将来暴露公网或共享给他人，这是首要收紧面。
- python 依赖系统 python3 与缺省 PATH，未做依赖声明与版本检查。
- 工具状态行只回报开始动作，不回报成败与耗时。
