# 2026-11-04 公网访问口令登录门卫

## 背景

服务此前只绑 loopback（`127.0.0.1`），公网不可达；要放到公网让远端壳与浏览器能用，就必须先堵"陌生人白嫖上游模型额度"这个口子。单用户自用工具的需求是"拦住外面的人"，不是"区分里面的角色"。

## 范围与非目标

- 管：所有静态页面/资源、所有 `/api` 端点的访问门槛；登录交互与会话维持。
- 不管：HTTPS 终止（nginx 已有证书，继续由它负责）；多用户/角色体系；限流、审计登录日志；Android 壳里的登录 UI（壳打开首页就是登录页，WebView 会话与浏览器一致，不改壳代码）。

## 考虑过的备选

- **HTTP Basic Auth**：否决——不能登出、浏览器弹窗体验差、口令每次请求都明文经过（虽有 TLS）；会话票更合身。
- **每次请求带 access key（header/query）**：否决——前端每个调用点都要改；密钥会进浏览器历史/代理日志/Referer。
- **第三方身份（OAuth/飞书登录）**：否决——自用单用户体量下纯属过度设计，还多一个外部依赖。
- **服务端会话表（内存 Map）**：否决——进程重启全员强制重登，自用场景徒增打断；无服务端状态的派生校验票对单用户足够，改口令即全局下线。
- **只拦 API、不拦静态**：否决——公网下首页代码与内容结构本身就暴露服务形态；门卫的意义是全站先过门。

## 最终方案与理由

单口令 + HttpOnly Cookie（`ACCESS_PASSWORD` 环境变量配置，默认关）。登录页是无构建依赖的静态 HTML（`GET /login.html` 由服务端直接返回），POST 口令到 `/api/auth`，验通过后 Set-Cookie 一条派生校验票（`签发秒.随机值.HMAC(口令)`，30 天）。静态侧未登录一律 303 引导到登录页；API 侧未登录一律 401 JSON。选这个的根本原因：**自用服务，安全目标是"陌生人进不来"，不是"细粒度授权"**——密码学强度由 HMAC+时序安全比较保证，体验上 30 天免重登，改口令一键全员下线。

## 豁免清单的设计纪律

未登录放行的路径不是拍脑袋列的，而是按"谁在发请求"对齐：

- 登录页自身 + PWA 启动必需（`/login.html`、`/manifest.webmanifest`、`/sw.js`、`/icons/*`、`/favicon.ico`）——不豁免的话浏览器连登录界面都画不出来、老壳安装时拉不到图标。
- `/api/auth`（登录端点自身）。
- `/api/app-version` + `/app/<apk>`——**老壳 OTA 的 DownloadManager 不带网页 Cookie**，拦了它等于合一次门卫把自动更新打死。这是最容易漏的一条：测再多次浏览器没 Cookie 的行为也发现不了。

## 遗留问题

- 登录失败没有限流，公网下口令可被高强度穷举；口令强度依赖人自觉。后续观察nginx日志再决定要不要加失败延迟或 fail2ban。
- 会话票只是一层 HMAC 校验，没有独立的会话随机性服务器侧记录——改口令才能全员下线，无法单独踢某个设备。单用户自用下暂可接受。
- HTTPS 由 nginx 负责，`AUTH_SECURE=false` 只是为绕过本机纯 HTTP 联调留的口子，公网部署必须保持默认 `true`。
