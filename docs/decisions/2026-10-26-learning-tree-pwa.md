# 2026-10-26 学习树：以问答树组织学习，用锚点替代串行对话

## 背景

用 AI 学习时，一问一答的串行结构不好用：读到回答中某一句想追问，只能在对话末尾提问，回答会跑到最后；想回看某个分支要来回翻，手机上尤其难。核心痛点不是"消息太多"，而是**锚点丢失**。

## 范围与非目标

- 本次只做个人自用、单机使用的移动端阅读体验。
- 不做账号体系、不做多端同步、不做分享与协作。
- 不上架应用商店：不涉及签名、隐私合规与商店审核流程。
- 不引入后端服务：数据与密钥都留在本机。

## 考虑过的备选

- **原生 Android（Kotlin + Compose）**：能拿到通知、后台、传感器能力，但本次需求全是阅读与交互，用不上；且需要先装 JDK 与 Android SDK（约 2~3GB），每次改动都要重新打包安装。否决。
- **Flutter**：可同时覆盖 iOS，但同样依赖完整 SDK，包体更大；单端自用收益不明显。否决。
- **PWA（Vite + React + TypeScript）**：浏览器直接跑，"添加到主屏幕"即可得到图标与全屏；改动即时生效；离线可用。采纳。
- **把追问展开在原文下方、层层缩进**：手机上宽度不够，两层以后正文就被挤没了。否决。
- **用侧边栏代替"进入分支"**：手机上侧边栏与正文争空间，且返回时容易丢失原位。否决。

## 最终方案与理由

- **锚点粒度取"选中的一段话"**：比整段点击更贴合"就这一句提问"的意图，也避免长段落里指代不清。回答按空行切成片段，每个片段可作为独立锚点容器。
- **用"进入分支 + 返回"代替缩进**：子问题以引子卡片贴在锚点片段下方，点开才进入该分支；返回时精确回到原片段并高亮锚点原文。深度交给导航，宽度留给正文。
- **树总览页兜底迷路**：列出整棵树骨架，可跳任意节点。
- **阅读现场存 `sessionStorage`**：滚动位置与返回锚点随标签页关闭失效，不污染长期数据。
- **锚点只存原文、不存偏移**：回答被重新生成后，按原文重新定位，尽量落回原处；定位不到时降级展示锚点原文。
- **单机持久化为唯一真相**：全部节点存 IndexedDB，一次事务整体替换；模型回答一律按不可信内容处理，渲染前经 DOMPurify 白名单过滤。
- **模型接入走 OpenAI 兼容协议**：国内主流服务商（DeepSeek、智谱、通义、Kimi）都提供兼容端点，一套适配器即可切换；密钥存 `localStorage`，只在本机。

## 遗留问题

- 直连模型接口依赖对方允许跨域；被拦截时需要自建代理，应用内暂无代理配置入口。
- 密钥以明文存于 `localStorage`，与本机浏览器同一信任域；设备共用场景下需自行规避。
- 长回答的流式生成尚未做增量渲染分片，生成过程中以纯文本展示，结束后才切分为片段。
