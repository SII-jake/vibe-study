# 决策记录的存放与格式约定

每个 PR 配一篇决策记录，记在 PR 最后定稿的 commit 里。

## 存放规则

- 目录：本目录（`docs/decisions/`）。
- 文件名：`YYYY-MM-DD-语义短名.md`，日期为 PR 定稿当天，短名全小写英文加连字符。
- **一个 PR 对应一篇**；同一 PR 的过程修订在原文件上更新，不留同日多篇。
- 一次提交的改动确实涉及两个不相关主题时，拆成两个 PR 各带一篇，不为一个 PR 凑多篇。

## 内容规则

只记取舍与理由，不复述代码 diff。推荐结构：

```md
# YYYY-MM-DD <决策主题>

## 背景
（为什么需要做这次决策）

## 范围与非目标
（本次决策管到什么边界；明确不写、不改、不做的事。方案层面的"不做"记在备选节，范围层面的"不做"记在本节）

## 考虑过的备选
（每条备选写一句否决或采纳的理由；否决项尤其要记）

## 最终方案与理由
（选定哪个、为什么选这个）

## 遗留问题
（没解决的、留待后续的，逐条列出）
```

- "范围与非目标"只记事前划的边界（动哪些域、不动哪些），不复述事后 diff 里能看到的东西。
- 不记会话操作痕迹——具体 commit SHA、"某分支即时执行了某操作"、修订元叙述一律不写；每句自问：一个月后读到的人需要它才能理解决策吗？不需要就删。
- 历史文档冻结不回填；后续更名、结构调整的脉络由当期 PR 的决策文档承载。
