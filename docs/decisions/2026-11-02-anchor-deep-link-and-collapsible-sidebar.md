# 2026-11-02 锚点可点开分支、左栏可收起与 SW 防自锁

## 背景

阅读区里被选中开过分支的原文只有下划线标记，不点击就回不去那条分支，得手动到左栏
找回哪条对话；桌面三栏把左栏会话列表常驻，窄视口下阅读区被挤。同期 PWA 暴露一个
更隐蔽的事故：Service Worker 旧版用 cache-first
且缓存无版本标识，旧页面把自己锁死在 Cache Storage 里，新版 sw.js 没机会执行，用户永远看到旧版。

## 范围与非目标

- 只动前端交互（锚点链接、左栏收起/展开）与离线缓存策略（Service Worker），不碰服务端与数据模型。
- 左栏收起/展开只做桌面与窄视口两态的展示切换，不重排中右栏的信息架构，不改对话树模型。
- 缓存策略只解决「自锁」与离线兜底两件事，不做预缓存清单之外的资源预热与后台同步。
- 不为锚点链接引入路由；分支跳转复用现有对话树导航。

## 考虑过的备选

- **锚点开分支做成浮层预览**：否决。用户意图是回到那条分支继续读/追问，进分支页一步到位；
  浮层多一层且不承载后续追问。
- **左栏收起用绝对定位浮出按钮**：否决。absolute 子项不占 grid 位，列模板切换时触发
  auto-placement 歧义，把主区塞进 0 宽列整片裁掉（已踩过一次）；改为收起态保留窄按钮列入流占位。
- **Service Worker 继续 cache-first、只改缓存内容**：否决。无版本标识的 cache-first
  结构性存在自锁路径，改内容不改策略等于留雷。
- **清缓存靠用户手动清站点数据**：否决。自锁下用户无感知也无入口，必须让 SW 自身留出升级
  解开的路径。

## 最终方案与理由

- 被选中开过分支的锚点原文渲染为可点链接，点击跳到已建分支；未开过的保持现有选中即建分支行为。
  理由：复用对话树导航，不新增状态。
- 左栏支持收起/展开：收起态保留一列按钮（展开、新会话、设置）在流内占位，主区显式钉列，
  消除 auto-placement 歧义；展开后恢复原列宽。理由：按钮列常驻占位列，两态都有确定几何。
- Service Worker 改为防自锁策略：HTML / sw.js / manifest / 接口一律 network-first（仅网络失败
  回退缓存），仅带指纹的 `/assets/*` 允许 cache-first，cache 名带版本段、升级时清同前缀旧缓存。
  理由：网络通时新版永远能到达页面，任何未来策略错误都能靠换 cache 名字段解开；
  配套服务端对入口文件回 `Cache-Control: no-store`。
- 新增真实浏览器 e2e happy path（`npm run test:e2e`）覆盖「载入示例→点锚点进分支→收起左栏→刷新保持→
  展开恢复」全链路，断言布局用几何事实（`getBoundingClientRect().width`、可见元素数）而非类名或模板
  字符串。理由：jsdom 无布局引擎，布局回归在单测层不可见，验收必须落到真实浏览器那一层。

## 遗留问题

- 左栏收起/展开仅在桌面视口做过完整验证；超窄移动端的手势与断点细节留待移动端专题。
- PWA 预缓存只含应用壳；分支对话内容尚不离线可读（缓存的是带指纹产物，不是接口数据）。
- e2e happy path 为单链路冒烟，未覆盖多分支并行、断点恢复等组合场景。
