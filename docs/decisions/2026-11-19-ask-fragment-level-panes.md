# 追问交互定稿：片段级锚点 + 双端分层视图

日期：2026-11-19。术语以 `docs/architecture.md` §一 术语表为准（追问/接着问/分支/层已登记）；本文是双端需求的唯一文字稿，实现前先红→绿。

## 背景

- 旧设计在备份分支 `feature/chat-ui-tools`（`pane-state.ts`/`track-view.ts`/`NodePage`/`AskPane`），经完整精读核实。
- 现状（DS demo 基座）：`askAt` 数据已是树，但视图无"层"概念——追问的问答不主动呈现，`AskBranches` 小卡片是"切版本"语义，与需求不符。
- 用户两轮拍板：锚点粒度**片段级**（不是消息级）；桌面端用轨道+双栏（旧 pane-state 语义），手机端整屏导航下潜。

## 一、共同数据模型

1. **片段级锚点**：回答按 AST 顶层块（段落/列表/代码/表格/公式各为一片段）编号 `fragmentIndex`，`MarkdownAstRenderer` 渲染时打 `data-fragment-index`；选区经 `closest('[data-fragment-index]')` 捕获。锚点三元组 = 锚点消息 id + fragmentIndex + 原文文字。
2. **兼容红线**：旧记录（无 fragmentIndex）自动退化为"整条回答一个片段"，不迁移数据；读写双方都按可选字段处理。
3. 追问 = 用户提问 + AI 回答的消息对挂到锚点消息下（现状结构保留）；追问的回答上可再追问（嵌套开放）。
4. **流式中禁止追问**（片段索引会漂移）；提问上下文沿锚点消息倒椎父链（已修过的口径不回退）。
5. 服务端零改动：`ask` 注记是客户端字段，nodes 同步原样透传；多端合并不感知片段级。
6. 视口状态只存 `{centerNodeId, rightNodeId}` 两个值（demo 基座的粒度是消息 id，桥到 pane 规则由纯计算桥接——见附录）；一切布局位移由四条纯函数推出，不写 React 状态。

## 二、桌面端需求（轨道 + 双栏）

> 稿源：旧 `pane-state.ts` 四条纯函数字面语义，逐字复述；结构红线出自旧 `track-stage.tsx` 顶部注释。

1. **视口结构**：对话链按层次从左到右铺成 lane 序列；**视口永远只框住最后两格**——中栏（当前对话）与右栏（起草位/子对话位）。中栏宽可拖，右栏吃余宽。
2. **结构红线**：位移 transform 只施加在轨道父容器，lane 不自带 transform——两格刚性相邻，"两块面板各动各的"的历史坑以本次定稿堵死。
3. **四条 pane 规则**（`pane-state.ts` 语义原文）：
   - `planPlaceChild`：子对话落位唯一规则——新子对话**一律进右栏**；右栏原有内容**先沉入中栏**（连续下潜）。
   - `planAsk`：中栏选文追问，两栏不动，右栏切起草态；右栏选文追问，当前右栏先沉中栏再起草。
   - `planPromote`（设为当前）：右栏升入中栏并清空右栏。
   - `planGoBack`（返回上一级）：视口左移一格——刚读的对话**留在右栏**，父子两级同时可读对照，不清空。
4. **右栏三态**：
   - 起草位 = AskPane 常驻：顶钉"就这段提问"+锚点原文引用；textarea，Enter 发送 / Shift+Enter 换行 / IME 组合中回车不发送；空态提示"选中一段文字，就能在这里开一条新的追问"。
   - 子对话位 = 紧凑形态消息流（去页头/底部追问条）+ 右栏顶栏（"子对话" + 设为当前 + ✕关闭）。
   - 无起草无子对话时空态。
5. **正文分支入口**：被选过的原文段落常驻下划线；片段下挂 AskCard 引子（💬 + 追问摘要 + "N 条追问 ›"）；**点卡片与点下划线同一路径：子对话进右栏**。返回到父层时来源锚点高亮为"返回到这里"标记。
6. **追问的问答不占中栏正文**——中栏正文只有下划线 + 片段下引子卡。

## 三、手机端需求（同一轨道，单 lane 视口）

> 用户 2026-11-19 定稿口径：手机端也是 lane 轨道，只是视口只框一格（`LANES_IN_VIEW=1`）。
> 双端共用"lane 轨道 + 视口钉某格"一个抽象（旧 `routeTrack()`/`singlePane` 已验证形态）：
> 桌面 `LANES_IN_VIEW=2`、手机 `LANES_IN_VIEW=1`；四条 pane 规则在单格视口下自然退化，
> 为两侧 pane-state 与 track 计算共用同一份纯函数的唯一保障。

1. lane 序列与桌面同一结构（当前节点+祖先依次排开）；每格铺满视口宽，**位移仍是轨道父容器一次 translateX**，视口钉在轨道末格=用户看到的"整屏下潜"；返回=视口右移一格（祖先 lane 一直在轨道上等着）。系统返回键先退层、再退应用（需壳桥拦截——落到实现时再验）。追问层顶栏：返回箭头 + 锚点原文钉顶引用框。
   - pane 规则在单格视口下的退化映射：`planPlaceChild` → 新 lane 生成 + 视口左移一格钉末格；`planGoBack` → 视口右移一格；`planAsk` → 起草用 AskSheet 底部弹层替代（单格视口无可见起草位，数据上追问仍是一条新 lane）；`planPromote` 手机端不适用。
2. 选中追问沿用已修的两段式：拖选中无遮挡 → 停顿出操作条「追问｜复制」（贴选区锚定，系统菜单抑制已修）→ 点追问进 **AskSheet**（底部弹层，锚点原文钉顶；textarea 同 IME 规则）。
3. **提交即导航**：提交=建子分支→立刻整屏下潜到子对话层；问答在该层流式渲染；该层的回答段落可再选文追问→再下一层。
4. **片段下引子卡**与桌面形态同款（片段级！）；点卡整屏下潜；返父层时来源锚点高亮。
5. 接着问（不选文）在当前层底部输入框直发，不开分支不下潜。

## 三补、真机实测修订（同日第一轮 OTA 后，8 条反馈的处置口径）
1. 手机端**恒走 TrackStage**（根态单格也在轨道上）——"根态回落裸 MessageList"招致提交瞬间"挂载即平移"无滑动；恒轨道使 lanes 1→2 与 offset 0→-屏宽在同一 `.track` 元素上发生，transition 生效。
2. **追问用户消息文字泡剥出系统前缀**：`message.ask` 存在时仅显示"我的追问："之后的问题本体（content 仍是给模型的协议格式，不动数据协定）；编辑态仍以完整 content 起草。
3. `buildMessageVersions` **按角色分键**：版本=同父同角色的兄弟分支；追问 user 消息与主线 assistant 共享 parentId 是分支结构（§二.6），不是"同一条消息的不同版"，不再凑出 `<2/2>`。
4. AskSheet/引子卡/lane 头样式**以 theme.css 中已定义的 token 为准**；未定义的 `--dsw-*` 引用会让整条声明失效（半透明弹层事故），style-guard 红线守护闭环。
5. 用户消息暂不可作为追问锚点（本次不放开 `readAskSelection`/`askAt` 的 assistant-only 边界；待另行决策）。
6. 点片段引子卡在**手机端**同样"整屏下潜"（openChild 的手机分流：centerNodeId 直移子分支根），不再有右栏语义。

## 四、非目标与红线

- BranchSwitcher（同槽位版本切换）保持原义，不与分支入口混。
- 服务端、同步、存储零语义改动；同步不感知片段级。
- 纯前端改动为绝大多数；壳配合仅返回键拦截一件（若需 bump 壳版本则按版本纪律办）。

## 实现顺序（红→绿依次）

1. fragmentIndex 片段编号 + 选区捕获升级（第一个失败测试先行）。
2. `pane-state.ts` 四条纯函数 + 单测（demo 基座落位）。
3. TrackStage 容器 + 中/右栏接入桌面端；AskPane 起草形态接入中栏选文流程。
4. 手机端 lane 堆栈 + AskSheet + 提交即导航；返回键分层。
5. AskCard 下划线 + 高亮"返回到这里"。
