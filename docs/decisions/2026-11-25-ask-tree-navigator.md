# 2026-11-25 追问树导航面板

## 背景

追问在数据上本来就是一棵树：每条追问挂到锚点消息下，回答上可再追问，层数不限。
但视图只能沿引子卡/下划线单向进入，再用「返回上一级」逐格退。追问一多、分支一交叉，
就找不回之前那条问答——用户不知道某条追问在哪一层、也不知道还有哪些分支存在。

现有视图只回答"我在哪"和"上一层是什么"，缺一个回答"整棵树长什么样、我在树的哪里"的
入口。这次补上它。

## 范围与非目标

- 只做浏览与跳转，不改存储、不改同步、不改服务端。树是现成数据的派生视图。
- 不做关键词筛选。用户明确本版不要；后续单独做搜索，且要同时搜提问与回答内容。
- 节点不展示答案摘要。用户判断"找问题"是主要动作，标题 + 来源片段够用；加答案首句
  会让行高翻倍、一屏能看到的节点数减半。
- 不改动 `docs/architecture.md`。「追问树」这个术语需要产品侧在 §一 术语表登记后再当
  权威口径使用；本文先按"追问树"字面称呼，不等同于已登记术语。

## 考虑过的备选

- **跳转把父级放中栏、目标放右栏**：能父子对照，但右栏窄，跳过去是要读那一层的完整
  问答，挤在窄栏里读不快。否决，选目标进中栏。
- **沿引子卡自动滚到对应段落**：只解决"同一层内定位"，解决不了"跨层找分支"——而后者
  才是痛点。否决。
- **侧滑抽屉常驻显示树**：给一个总是占地方的面板，绝大多数时间没在用；追问少的会话
  更是纯负担。改用按需打开的居中弹层。否决。
- **给树行加筛选框**：见非目标。否决（本版）。
- **树节点用消息 id 直接铺**：一条追问产出 user+assistant 两条消息，按消息铺会把一件
  事拆成两行。否决，节点取追问分支的根用户消息（lane 根），与既有 lane 概念对齐。

## 最终方案与理由

**数据**：派生，不新增存储。节点 = 追问分支的根用户消息；子节点取法与右栏、引子卡
完全同一口径——对该 lane 根重根取可见链，再在可见 assistant 消息上取引子卡列表。
不发明第二套遍历，树与正文陈列面永远一致。

**跳转**：新增第五条 pane 规则 `planJumpTo`：目标进中栏、右栏清空。桌面端祖先链照常
铺开（目标左侧仍是父层，父子对照不丢），手机端单格视口自然退化成整屏下潜。不复用
`planPromote` 是因为它只在右栏有内容时才动，而跳转与右栏状态无关。

**入口**：与「返回上一级」并排。桌面用文字，空间充足更清楚；手机用图标（文字会挤占
标题宽度）。手机的「返回上一级」也一并改成图标：向左箭头是通用返回语义，把文字位置
让给标题；按钮尺寸与菜单/新对话同规格，不因换图标而变小。会话里没有任何追问时不显示
入口——没有树可看。

**面板**：复用既有 Modal（遮罩、Esc、点遮罩关闭、叠放只关最上层都有现成语义）。
默认只展开到当前位置，其余折叠，另有「全部展开/全部折叠」；追问多时全展开就是一面
文字墙，折叠后逐层辨认仍比逐层进出快。

**沉底追问**：挂在已脱离可见链的回答之下（例如那条回答被编辑后的新版本替换）的追问，
树遍历不到，但记录还在。这类统一收在树尾标记「沉底」扁平陈列——用户想找的往往正是
当时没追完的那条，入口不能静默消失。

**返回键分层**：面板开着时系统返回键只收面板，不退层。一次按键掉两级、还顺带丢了
用户刚打开的面板，是最容易招骂的交互。
