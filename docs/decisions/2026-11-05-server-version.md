# 双版本号：应用版本（壳）与服务端版本并列

## 背景

发布一轮纯前端体验改进后，用户在设置页看到「当前版本 1.0.2」纹丝不动、检查更新提示「已是最新版本」——版本号口径只有壳 versionName 一个，纯前端发布（不发新 APK）在版本上完全不可见。用户定调：保持「纯前端不 bump 壳版本」的纪律（A 方案），但要分出第二个版本号——**服务端版本**，随每次发布前进。

## 范围与非目标

- 壳版本（`android/app/build.gradle` versionName）的既有纪律不动：只有原生改动才 bump，OTA 比对链路零改动。
- 服务端版本只回答「当前服务是哪次发布的」，每次 `release.sh` 发布自动 +1，不需要人工记。
- 不做跨设备版本一致性约定（服务端版本是部署环境的本地序号，不是全局语义化版本）。

## 考虑过的备选

1. 构建时间戳当服务端版本（如 2026.11.05.1732）：可直接看出发布时间，但看不出发布序数、无法从串上判断早晚。
2. 服务端版本独立语义化（0.1.0→0.1.1，与壳无关）：两套进位规则并存，谁是主版本要靠记。
3. 服务端版本 = `<壳版本>.<发布序号>`（如 1.0.2.7）：壳版本一眼可辨其基线，序号每次发布 +1；壳 bump 时序号自然归 1 重新开始。

## 最终方案与理由

选 3。发布脚本 `release.sh` 自增 `dist/app/.release-seq`（publish-apk.sh 只清 *.apk，隐藏文件跨构建存活；实测验证），写出 `dist/server-version.json`。`/api/app-version` 响应增加 `serverVersion` 字段（200/404 都带——纯前端发布无 APK 时设置页也要能报出版本）；老部署无此文件时回退壳版本，新旧口径无缝衔接。设置页双行展示「应用版本 / 服务端版本」，无桥浏览器只显示服务端版本行。健康检查加对拍 `serverVersion`，发布完成信息印有双版本。

## 遗留问题

- `.release-seq` 只活在 dist/app/ 里，dist 整个被重建/清空的部署环境会从 1 重新计数（可接受：序号只服务「同环境下比早晚」）。
- 启动页 boot.js 的版本提示文案仍只报壳版本（OTA 语义本就只对壳），不在本批范围。
