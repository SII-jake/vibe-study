# 代码规范与开发后自核清单

本仓的工程规范与典型反面案例。每次开发完成后对照逐项过一遍。内容分两半：DRY（Don't Repeat Yourself）与文档/注释的正式简洁用语。

## 一、DRY — 同一份知识只有一个归属地

### 1. 同一意图写成中文 + 英文两份注释

**反面形态**：docstring 用英文写一遍意图，旁边或下面再用中文复述一遍（或反过来）；git diff 里同时出现意思相同的两段说明。
**判定做法**：每个附着点只写一遍意图。docstring 说"做什么、为什么"；行内注释只在"不看解释读不懂这段代码"的位置写，且不复述代码可见的事实。发现同义两处就删其一。

### 2. 两个功能近似的函数并存

**反面形态**：`_load_frames` 与 `_load_frames_by_scope` 内部 90% 逻辑相同、只是参数不同；或同一能力存在 `build_x` 与 `build_x_v2` 两个入口。
**判定做法**：同一能力只允许一个公开入口。分支差异通过显式参数或常量登记表达，不再裂变出新近似函数。修改时若在 git diff 里同时触碰两个近似函数，先停下来判断"是不是该合并其一"。

### 3. 同义改写的词汇（同一概念两个词）

**反面形态**：同一指标在不同模块里叫两个名字；接口默认字段是一种写法，统计结算处变成另一种写法；CSS 前缀一半 `section-` 一半 `sector-`。
**判定做法**：术语唯一事实源是 `docs/architecture.md`。模块名、函数名、常量名、类型字段、表名列，全部按文档原词照抄。发现旧的同义词（含 CSS 前缀、路由 slug）时**直接替换为权威术语，不留 alias 或兼容 shim**。
**实例登记**：本仓发生过的替换记在此处，含 commit 引用（初始为空，随用随记）。

### 4. 语义变了名字没改（拿改注释顶替改名）

**反面形态**：功能修改后函数语义已经变化，函数名却沿用旧名，只更新注释来掩饰偏差；文件名、目录名同理——职责早已转移，名字照旧沿用，靠改注释或 README 来"交代"。
**判定做法**：语义变化使现有名字不再准确时，必须连名字一起改对——函数改名、文件改名、目录改名；改注释只是配套动作，不许拿它顶替改名。改名时同步改全部引用方与相关文档，不留旧名 alias 或兼容入口；新名字按术语唯一事实源 `docs/architecture.md` 取词。

### 5. 同一份数据有两个写入方

**反面形态**：同一份文案既在页面模板里写死了一遍，又在数据字典里登记了一遍；或同一指标值被两个 builder 分别算一遍。
**判定做法**：每份数据只有一个 owner。owner 之外的消费点必须引用 owner 的输出，不得自行再算或再写一份。改契约 key 时同步改所有引用方（字典、类型、模板），不允许某一处还留着旧写法当 fallback。

### 6. 同一段判断逻辑被复制到多处

**反面形态**：同一个"合法性/归一化"判断在 A 模块手写一遍，在 B 模块换了个写法又写一遍（如路径校验、key 归一）。
**判定做法**：抽出到共享 helper，调用方只调用。写第三处同类判断时，先查现有 helper 有没有现成实现。

## 二、文档与注释的正式简洁用语

1. **一句话只讲一件事**；多个事实分多句写。
2. **不写营销词**。"极大提升"、"最佳实践"、"无缝集成"这类表达一律删除。
3. **术语照抄 `docs/architecture.md`**，不自由发明近义词。
4. **用量词而非模糊动词**。"取最新记录"而不是"拿下最新那个"，"按日期汇总"而不是"按日期搞一搞"。
5. **注释主体用中文，代码标识符与字段名保留其英文原样**，不要为行文统一去改写它们。
6. **markdown 源码一完整句一行**，不在半句话中间换行（本文件即按此书写）。
7. **git commit message 用 conventional 形式**：`type(scope): subject`；subject 用动词开头说清改了什么；body 说明原因与验证证据。禁止 "fix stuff"、"update code" 一类无信息量标题。
8. **分支命名与 commit type 对齐**：进入 PR 的分支一律 `<type>/<语义短名>`；type 取 commit message 同一集合（feature|fix|docs|refactor|chore|test|perf），短名全小写英文加连字符。**反面形态**：`zhangsan-dev`（人名当分支名，看不出这个分支做什么事）、`update-0915`（日期当短名，类型缺失）。工具自动生成、不进入 PR 的隔离分支（如 `synergy/*`）不受此限；存量不合规分支不改名、不追讨，只约束新增。
