# push 前检查清单

每次 push 代码到远端前逐项过一遍。每项只接受三种状态：通过、不适用（写明理由）、未通过（写明原因）。
勾不出来的项必须在 PR 里显式报给人，不许静默跳过——勾不满又不说，视同检查未做。
这份清单只列检查动作；每项对应的判定做法与案例在各被引用文档里。

## 验证专员（独立核查，非强制）

把 checklist 的三态结果拿到一个**未参与实现的**校验通道（独立会话/独立 agent/同事）复核——尤其是一、二两节的命令是否真的跑过、输出能否复现。核查结果以 PR 评论形式落地。核查不是强制环节，reviewer 要求时执行；核查产出是"我确认/我发现问题"的证据，不代替实现人负责。

## 引用文档（检查标准所在地）

- 代码规范与反面案例：`docs/code-standards.md`。
- 分域改动风险：`docs/risks/` 下对应文件。
- 系统设计唯一权威：`docs/architecture.md`。

## 检查项

### 一、验证命令全部跑通

- [ ] `[测试命令]` 全绿。
- [ ] `[类型检查/静态检查命令]`（如有）无错误。
- [ ] 涉构建的改动 `[构建命令]` 成功。
- [ ] 按项目追加：如数据任务改动需跑批成功并产出齐全、特定对外契约改动需受影响产物重建等。

### 二、测试先行（行为类改动）

- [ ] 行为改动/bug 修复有对应测试，且测试先于实现出现（红→绿）。纯视觉/样式/文案改动例外。

### 三、代码规范自核（对照 `docs/code-standards.md`）

- [ ] 没有中英文两份复述同一意图的注释。
- [ ] 没有与新写函数 90% 重合度的旧函数残留。
- [ ] 没有同义改写术语——所有新标识符都能在 `architecture.md` 或其引用注册表（常数定义、类型定义）里找到对应原文。
- [ ] 同一份数据只有一个写入方；不存在第二个兜底旁路副本。
- [ ] 没有重复实现的判断逻辑（校验、归一化等判断优先复用现有 helper）。
- [ ] 文档与注释一完整句一行；无营销词；术语照抄 architecture.md。

### 四、分域风险自核（对照 `docs/risks/` 对应文件）

> 按项目分域各留一节，把 risks 文件里的高频项提升为本节检查项。

改 [域A] 时：

- [ ] [按域填写高频项]

改 [域B] 时：

- [ ] [按域填写高频项]

### 五、Git 流程

- [ ] 当前分支是新分支；PR 目标默认为 `[主开发分支]`。
- [ ] 分支名符合 `<type>/<语义短名>`（type 取 feature|fix|docs|refactor|chore|test|perf，短名全小写英文加连字符，不带人名、日期）；工具自动生成的隔离分支例外。
- [ ] commit message 为 conventional 风格（`type(scope): subject`）；body 说明改了什么、为什么、验证证据。
- [ ] 对话中途的零散进度 commit 未逐个 push 到远端；push 前已将其 squash 成按"完整一件事"组织的历史并一次性推送（铁律 8）；远端已挂半成品历史时，删掉远端分支重推或换分支后再 push。
- [ ] 本次 PR 的关键思考与决策已整理为一篇 md 文档放入 `docs/decisions/`（文件名 `YYYY-MM-DD-语义短名.md`，日期为 PR 定稿当天）；与改动同 commit；多轮过程修订在原文件上更新，不留同日多篇。
- [ ] 决策文档只记取舍与理由（背景、范围与非目标、考虑过的备选、最终方案与理由、遗留问题），不复述代码 diff，不记会话操作痕迹（SHA、即时执行记录、修订元叙述）。
- [ ] 本次 PR 由人明确指令触发，非代理自行决定（铁律 8）。

## 经验积累（当发现了新坑如何登记）

- 某分域的技术坑：写入 `docs/risks/<域>-risks.md`（新条目加在最上方）。
- 与代码规范相关的坑（中英文双份注释、近似函数并存、同义改写术语等）：写入 `docs/code-standards.md` 对应条目。
- 协作过程导致的坑与返工事件（规格不清、静默跳过、带病开工等）：按 `docs/agent-collab-metrics.md` 的格式登记。
- 退役内容与归档归口：`docs/archived/`（规则见其 README）。
- 需要进入本清单的新检查项：直接在本文件相应小节的末尾追加，不改其它条文。
